# NEXUS plugins — Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for local implementation and one independent final review. No commit, push, publication or global installation is authorized.

**Goal:** Package the existing NEXUS skill for Claude Code and Codex with one shared source.

**Architecture:** Two compatibility manifests at the repository root point to `skills/`. Local marketplace catalogs expose `nexus@nexus-local`. Helpers remain explicit; the separate textual runtime is not activated by installation.

**Tech Stack:** JSON, Markdown, Python 3.10+ standard library; existing POSIX helpers.

**Spec:** The recommendation approved in this conversation: first deliver the basic plugin and isolated installation checks; native hook adapters are a later increment.

## Global Constraints

- `skills/nexus/` remains the only source of the portable skill.
- No new dependencies, MCP server, automatic hooks or native agents.
- No global configuration changes, license selection, release or commits.
- State lives in the consumer workspace, outside the installed plugin cache.
- Preserve host permissions, model policy and manual helper activation.

## Review Focus

- Loading a plugin from a path containing spaces in another workspace.
- Immutable package cache and state surviving package replacement.
- Missing or inconsistent manifests/catalogs must fail validation.
- Installation must not register executable hooks or load the optional API runtime.
- CLI discovery proves installation, not model compliance or authenticated provider behavior.
