# Local Hook Engine Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for implementation in this worktree. No commit, push, installation or native hook registration is authorized.

**Goal:** Deliver the explicitly authorized local Python executor and failure tests.

**Architecture:** Explicit JSON event calls, a reviewed JSON registry, built-in handlers and opt-in commands. A local SQLite journal claims events before effects and serializes work per workspace; uncertain executions require reconciliation. No provider SDK, daemon, queue or LLM calls.

**Tech Stack:** Python 3.10+, standard library; POSIX for process-group cleanup.

**Spec:** User-approved scope: local executor, deterministic handlers, tests, native integrations disabled. Contract and usage live in `skills/nexus/references/hooks.md`.

## Constraints and decisions

- Source of truth stays under `skills/nexus/`; tests and evidence stay in this repository.
- Modes OBSERVE/ADVISE cannot execute commands or write memory. ENFORCE affects only the CLI gate; it does not control the host.
- SQLite is local, one state path shared by all callers for a workspace. No distributed locking guarantee.
- Command output is discarded; no secrets or raw event payloads in telemetry. Registry and command paths are operator-trusted configuration.
- A crash never authorizes replay. Reconciliation releases a workspace only after the caller has checked effects and stopped orphan processes.
- Memory persists only synthetic/explicitly supplied content with provenance and an expected version. No automatic conversation capture.
- Evidence is valid only for the explicit file scope and registry digest. No global completion claim or unmeasured latency target.

## Review focus

Same event ID with changed payload; concurrent processes; process death after an effect; stale evidence after edits; hidden authorization escalation through registry modes.
